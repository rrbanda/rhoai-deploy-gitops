REPO STRUCTURE

Repository Architecture

Three directories, one ConfigMap, everything is discoverable.

rhoai-deploy-gitops/ ├── bootstrap/ # One-time entry point │ └── overlays/default/ │ ├── cluster-config.yaml # Single source of truth │ ├── kustomization.yaml # Kustomize replacements │ └── gitops-controller.yaml # Self-management (wave 10) ├── components/ │ ├── operators/ # 12 operator directories │ │ ├── rhoai-operator/ # NS + OG + Subscription per dir │ │ ├── cert-manager/ │ │ ├── servicemesh/ │ │ ├── kueue-operator/ │ │ └── ... (8 more) │ ├── instances/ # 24 instance directories │ │ ├── rhoai-instance/ # 6 DSC profiles (overlays) │ │ ├── nfd-instance/ │ │ ├── maas-postgres/ │ │ └── ... cluster-config.yaml is a ConfigMap with 4 fields: repoURL, targetRevision, rhoaiChannel, rhoaiOverlay. Kustomize replacements inject these into all 4 ApplicationSets + 2 standalone Applications.

This is the key architecture slide. Everything flows from cluster-config.yaml. 4 operators use redhat-cop/gitops-catalog as remote Kustomize base pinned at commit 7727f242.
PATTERN

The App-of-Apps Pattern

4 ApplicationSets auto-discover directories. Add a dir, push, ArgoCD creates the Application.

ApplicationSets use Git directory generators. Each scans a path (e.g. components/operators/*) and creates one ArgoCD Application per subdirectory. Exclusions are configured directly in the AppSet YAML.
PHASE 4

Bootstrap: 7 Layers in One Command

oc apply -k bootstrap/overlays/default — after this, Git is the only interface.

  1. GitOps Operator — Subscription + ClusterRoleBinding
  2. ArgoCD Instance — Helm + Kustomize enabled, health checks for DSC/DSCI CRDs
  3. cluster-config ConfigMap — repoURL, targetRevision, rhoaiChannel, rhoaiOverlay
  4. AppProjects — platform (operators/instances) + usecases (models/services)
  5. 4 ApplicationSets — auto-discovery engines for operators, instances, models, services
  6. rhoai-dsc Application — separate from AppSet (Replace sync + status ignore + retry config)
  7. gitops-controller — self-management at wave 10 (ServerSideApply, last to sync)

CRD timing: The bootstrap uses an until loop because the ArgoCD CRD isn't immediately available after the GitOps operator is installed. In our deploy, it succeeded on attempt 3 (10s sleep between retries).

After bootstrap, you never run oc apply again. Everything is managed through Git pushes. The gitops-controller at wave 10 watches itself — ArgoCD managing ArgoCD.

ORDERING

Sync Waves & Dependency Ordering

ArgoCD sync waves ensure resources are created in the correct order. Operators before instances, instances before DSC.

1OperatorsOperator SubscriptionsAll 12 Subscriptions, monitoring-config CM
2InstancesBasic instance CRsKuadrant, Backstage, ClusterAutoscaler

Sync waves are the ordering mechanism. They prevent CRD-not-found errors by ensuring operators install before their CRs are applied.

SECURITY

Secret Management Pattern

Never commit real credentials to Git. Three layers ensure secrets are safe and ArgoCD doesn't revert them.

Prune=false annotation on the Secret prevents ArgoCD from deleting it. ignoreDifferences prevents ArgoCD from reverting the real value back to the placeholder.

This pattern keeps secrets safe: placeholder in Git, ArgoCD ignores the data fields, and the real value is set on-cluster. External Secrets Operator is already deployed for long-term automation.

Day-2 Operations

After bootstrap, everything is a Git push. Here's how common operations work.

Add an Operator
Create dir under components/operators/ → push → ArgoCD auto-discovers via ApplicationSet
Change DSC Profile
configure.sh --dsc serving → push → ArgoCD reconciles the DSC overlay
Enable a Model
configure.sh enable-model gemma2-9b-fp8 → push → model Application created
Upgrade RHOAI
configure.sh --channel fast (when GA) → push → OLM upgrades the operator
Rotate Secrets
oc patch secret on cluster → ArgoCD ignores the diff (ignoreDifferences configured)
Troubleshoot Stuck Apps
ArgoCD dashboard shows diffs; oc annotate ... refresh=hard for retry-exhausted apps
Every common operation maps to either a Git push or a single oc command. The ArgoCD dashboard is the primary troubleshooting interface.
